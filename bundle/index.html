Where the events go

freiheit.com 02.2026 — present Java · Kafka · Salesforce (Apex) · GCP · Grafana · Testcontainers

Enterprise logistics platform migration

A global shipping platform moving off a legacy stack onto a CRM-backed one, with Kafka in the middle and a downstream consumer that could not keep up. I designed and built the Java middleware that sits between them: it drops events the target system will never care about, and holds out-of-order events until the ones in front of them arrive, so the sequence downstream is the sequence that actually happened.

  • Cut load on an overloaded downstream consumer by ~70%, materially improving end-system stability
  • Main topic averages ~5M events/day across 12 partitions
  • Ran the production cutover in a 15-minute window — copied consumer offsets, switched consumer group config, lost nothing
  • Worked both sides of the seam: Apex classes, triggers and unit tests in Salesforce, plus the service turning Kafka events into HTTP calls to it
  • Set up the project scaffolding and CI/CD to the client's engineering standards; integration tests with JUnit and Testcontainers; Grafana dashboards and alerts for throughput and failures
  • Run requirements sessions with the client and act as technical point of contact between them and an external development partner
